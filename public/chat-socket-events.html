Chat Socket Events

Socket.IO chat ke har implemented event ka naam, client payload, acknowledgement response aur server broadcast yahan diya gaya hai.

Shuru karne se pehle

Identity server se aati haiChat handlers user ID ko authenticated socket se lete hain. Chat payload mein apna userId ya role bhejne ki zaroorat nahi.
Room pehle se hona chahiyechat:join_room room create nahi karta. Booking flow ko server-side ChatService.createRoom() se room pehle banana hai.

Socket connect

Server handshake query mein user_type, user_id, aur guest_id validate karta hai. Chat ke liye guest connection kaam nahi karega, kyunki guest ka authenticated numeric userId null hota hai.

import { io } from 'socket.io-client';

const socket = io(SERVER_URL, {
  query: {
    user_id: String(currentUser.id),
    user_type: currentUser.role, // customer, driver, ya admin
    guest_id: '0'
  }
});

Server customer, driver, aur admin user types allow karta hai. Chat authorization room owner/participant membership aur numeric user ID se hoti hai.

Acknowledgement format

// Success
{ "success": true, "message": "...", "data": { } }

// Failure
{ "success": false, "message": "...", "errors": null, "code": 500 }

Acknowledgement sirf un client events par aata hai jinke example mein callback diya gaya hai. `typing_start` aur `typing_stop` acknowledgement nahi dete.

Room events

chat:join_roomClient → Server · Ack

Existing booking room join karein. bookingId ya roomId mein se ek bhejein; user identity socket auth se li jaati hai.

socket.emit('chat:join_room', { bookingId: 12345 }, (response) => {
  if (!response.success) return showError(response.message);
  const { room, history, participants, isOwner } = response.data;
  openChat(room.id, history);
});

Success data: { room, history, participants, isOwner }. Owner ko sab conversations ki history dikhti hai; participant ko sirf apni owner conversation ki.

Validation: Dono IDs na bhejne par bookingId is required. Room missing/closed ya access-related service error par ack mein success: false.

chat:get_order_roomsClient → Server · Ack

Booking ka room fetch karein. Is handler mein joinRoom() call hota hai, isliye non-owner user participant ke roop mein add/reactivate ho sakta hai. Yeh socket ko Socket.IO room mein join nahi karta.

socket.emit('chat:get_order_rooms', { bookingId: 12345 }, (response) => {
  if (!response.success) return showError(response.message);
  const rooms = response.data; // array, aam taur par ek room
});

orderId bhi backend accept karta hai, lekin naye client code mein bookingId use karein. Success message Booking room fetched.

chat:leave_roomClient → Server · Ack

Current socket ko chat broadcast room se remove karein.

socket.emit('chat:leave_room', { roomId: 10 }, (response) => {
  // { success: true, message: 'Left room', data: null }
});

Isse database participant membership delete nahi hoti. roomId missing ho tab bhi handler success ack bhejta hai.

chat:get_participantsClient → Server · Ack

Room ke active participants ki current list lein. User ko room ka owner ya active participant hona chahiye.

socket.emit('chat:get_participants', { roomId: 10 }, (response) => {
  if (response.success) renderParticipants(response.data);
});

Data: participant objects ka array. Har object mein userId, name, joinedAt, isOwner, socketId, socketIds, aur isOnline hain.

{
        "userId": 8,
        "name": "Aman Khan",
        "joinedAt": "2026-10-21T10:02:00.000Z",
        "isOwner": false,
        "socketId": "abc123-current-socket",
        "socketIds": ["abc123-current-socket", "xyz789-another-device"],
        "isOnline": true
      }

socketIds us user ke sabhi currently connected Socket.IO connections hain. socketId compatibility ke liye pehla active socket ID hai, warna null. isOnline live connection list se calculate hota hai.

chat:room_joinedServer → Room

Koi user room join kare to pehle se room mein maujood sockets ko emit hota hai. Join karne wale socket ko yeh event nahi milta.

{
  "room": { "id": 10, "room_booking_id": 12345, "room_owner_id": 4 },
  "joinedBy": { "userId": 8 },
  "participant": { "participant_user_id": 8 }
}

Join karne wale client ko room, history aur participants `chat:join_room` ack mein milte hain.

Messages

chat:send_messageClient → Server · Ack

Text ya attachment message save karke authorized conversation clients ko bhejein. Room join/access valid hona chahiye.

Participant se owner ko

socket.emit('chat:send_message', {
  roomId: 10,
  message: 'Pickup point par pahunch gaya hoon.',
  messageType: 'text'
}, (response) => {
  if (response.success) console.log(response.data.id);
});

Owner se specific participant ko

socket.emit('chat:send_message', {
  roomId: 10,
  toUserId: 8,
  message: 'Gate par milte hain.',
  messageType: 'text'
}, callback);

Owner ke message mein toUserId required hai aur woh room ka active participant hona chahiye. Participant ke liye target automatically room owner hota hai.

Attachment

socket.emit('chat:send_message', {
  roomId: 10,
  message: null,
  messageType: 'image',
  attachmentUrl: 'https://cdn.example.com/photo.jpg'
}, callback);

messageType omit karne par database default text hai; attachmentUrl omit karne par null hota hai. roomId aur message ya attachmentUrl required hain.

Ack data: database se saved message row (response.data), success message Message sent.

chat:new_messageServer → Authorized Clients

Message save hone ke baad relevant conversation ke clients ko success/message/data envelope mein emit hota hai.

{
  "success": true,
  "message": "New message",
  "data": {
    "id": 501,
    "chat_room_id": 10,
    "chat_sender_id": 8,
    "chat_conversation_user_id": 4,
    "chat_message": "Pickup point par pahunch gaya hoon.",
    "chat_message_type": "text",
    "chat_attachment_url": null,
    "chat_message_status": "sent",
    "created_at": "2026-10-21T10:00:00.000Z"
  }
}

Owner ko apne room ke sab conversation messages milte hain. Participant ko sirf apni owner conversation ke messages milte hain; doosre participants ko nahi.

chat:get_room_historyClient → Server · Ack

Room history page-wise fetch karein. Default page 1, default page size 50; response oldest-to-newest order mein hota hai.

socket.emit('chat:get_room_history', { roomId: 10, page: 1 }, (response) => {
  if (response.success) renderMessages(response.data);
});

Data: message rows ka array. Access check hota hai. Owner ko sab threads ki history; participant ko sirf apni thread ki history.

Typing aur read receipts

chat:typing_start / chat:typing_stopClient → Server

Typing state notify karein. Dono events payload mein roomId lete hain; callback/ack nahi hai.

socket.emit('chat:typing_start', { roomId: 10 });
socket.emit('chat:typing_stop', { roomId: 10 });

Room access valid ho to sender ke alawa room ke clients ko chat:user_typing milta hai. Invalid room/access errors silently ignore hote hain.

chat:user_typingServer → Room

{ "roomId": 10, "userId": 8, "isTyping": true }

isTyping start par true, stop par false. Yeh event success/data envelope mein nahi hota.

chat:mark_readClient → Server · Ack

Current user ki visible conversation mein doosre user ke unread messages ko read mark karein.

socket.emit('chat:mark_read', { roomId: 10 }, (response) => {
  if (response.success) console.log(response.data.markedCount);
});

Ack data: { markedCount: number }. Naye messages mark hue hon tabhi read broadcast emit hota hai.

chat:message_readServer → Room

{
  "roomId": 10,
  "messageIds": [501, 502],
  "readBy": { "userId": 4 },
  "readAt": "2026-10-21T10:05:00.000Z"
}

Raw object broadcast hota hai, response envelope nahi. readAt ISO timestamp hai.

Registry mein listed, abhi emit nahi hote

Client listener par abhi depend na kareinEvent registry mein naam hona is baat ka proof nahi ki current handler usse emit karta hai.
EventCurrent statusAvailable behavior
chat:message_deliveredNot emittedRegistry mein declared hai; chat handler mein delivery receipt emit nahi hota. Model mein markDelivered() helper hai, lekin is flow se wired nahi.
chat:order_rooms_listNot emittedRegistry mein declared hai; current chat:get_order_rooms response acknowledgement se milta hai.

Recommended client flow

  1. Booking create hone par trusted server flow se booking ka chat room create karein.
  2. Client authenticated socket connect karke chat:join_room emit kare.
  3. Join acknowledgement se room.id, history aur participants store karein; chat:new_message listener connection ke baad register rakhein.
  4. Participant message bhejte waqt roomId bheje; owner message mein toUserId bhi de.
  5. Chat visible hone par chat:mark_read call karein; screen close par chat:leave_room emit karein.
